## Choose an entry point

| What you need                                                  | Where to go                                                                                                     |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Connection, sync, rendering, or visual implementation problems | [Bug report](https://github.com/tarot-ai-labs/tarot-pixel/issues/new?template=bug-report.en.yml)                |
| A new capability or an improvement to your workflow            | [Feature request](https://github.com/tarot-ai-labs/tarot-pixel/issues/new?template=feature-request.en.yml)      |
| Missing instructions, broken links, or unclear wording         | [Documentation feedback](https://github.com/tarot-ai-labs/tarot-pixel/issues/new?template=documentation.en.yml) |
| Usage questions, examples, or open discussion                  | [Discussions](https://github.com/tarot-ai-labs/tarot-pixel/discussions)                                         |

Search existing reports first. If you find the same problem, add your environment and observations to that discussion.

## Help us understand the problem

The most useful details are the step where the problem occurred, what you expected, and what happened. For visual problems, a close-up comparison of the design and actual result helps.

Include environment and version details when you can, but “Not sure” is fine. Screenshots, logs, and design files are optional. Sanitize customer or internal data before sharing it; see [data and privacy](docs/en/privacy.md).

You need to sign in to GitHub to submit feedback. Maintainers follow up in the Issue or Discussion, so you do not need to publish an email address, phone number, or other personal contact information.

## How feedback is handled

Reports in both languages share the same workflow and status labels:

| Repository label | Meaning                                                                     |
| ---------------- | --------------------------------------------------------------------------- |
| `待确认`         | Needs triage: received and awaiting review or reproduction                  |
| `需要补充`       | More information needed: the maintainer will explain what is missing        |
| `已确认`         | Confirmed: the issue or request has been verified and awaits scheduling     |
| `处理中`         | In progress                                                                 |
| `已发布`         | Released: the reply will include the relevant version or documentation link |

Types use labels such as `bug`, `enhancement`, and `documentation`. Duplicate reports link to the original. If a suggestion is not adopted, the reason will be explained. Fixes are considered available when actually released and confirmed by maintainers; no fixed response time is promised.
