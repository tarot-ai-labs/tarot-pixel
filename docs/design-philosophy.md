# 视觉上下文

**简体中文** · [English](en/design-philosophy.md)

[返回首页](../README.md) · [开始使用](quick-start.md)

传统 D2C 通常把设计稿转换成一版代码。选中某个节点后调用 Design To Code MCP，则把当前选区的设计信息交给 Agent，用于当前任务，读取设计的起点由用户选中的节点决定。

Tarot Pixel 提供的是一份可持续查询的视觉稿结构化数据。设计同步后，Agent 可以在已同步的范围内查找页面、模块和图层，根据任务读取对应的布局、样式及图片资源。用户给出要完成的任务，Agent 再去设计中定位需要的内容，并在开发过程中继续查询。

例如，实现商品卡片时，Agent 可以先找到卡片所在的模块，了解整体结构，再读取标题和按钮的具体样式。页面运行后发现间距不对，可以重新查询相关图层；接下来要修改其他区域，也可以沿着设计结构继续查找。视觉稿更新后，重新同步即可读取新的数据。

这份视觉上下文与需求、代码上下文一起参与开发。业务需求说明功能如何工作，现有代码提供组件和实现约定，Tarot Pixel 则持续提供视觉稿中的设计依据，由 Agent 结合这些信息完成实现和修改。
