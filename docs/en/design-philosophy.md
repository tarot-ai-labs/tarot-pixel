# Visual context

[简体中文](../design-philosophy.md) · **English**

[Home](../../README.en.md) · [Get started](quick-start.md)

Tarot Pixel organizes designs into reference material an agent can revisit: from page overviews to individual layers, and from layout values to visual assets.

When building a product card, the agent can start with the overview, then look up title styles, button spacing, and background layers. It combines those details with existing components, price data, and click behavior in your project.

- **Query designs as needed.** Locate a page or module, then read the nodes, styles, and assets relevant to the task.
- **Build within your project.** Reuse components and styling conventions so dynamic content, business states, and visuals work together.
- **Revisit and refine.** When a preview reveals a difference, query the relevant design nodes and update the implementation.

For example, complex lighting effects can become a background image while the title, price, and button remain code for dynamic content and interaction.
