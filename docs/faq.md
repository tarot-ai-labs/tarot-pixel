# 常见问题

[返回首页](../README.md) · [提交问题](https://github.com/tarot-ai-labs/tarot-pixel/issues/new?template=bug-report.yml)

## Agent 看不到 Tarot Pixel 工具

确认插件或 MCP 服务已启用，在新会话中调用 `server_status`。使用 npm 配置时检查 Node.js 版本、网络和客户端的 `PATH`。如果客户端要求单个服务对象，请按该客户端格式填写配置。[安装指南](installation.md)提供完整示例。

## 已安装设计工具插件，为什么还无法同步？

设计工具插件负责导出，本地 Runtime 负责接收。先启动已连接 Tarot Pixel 的客户端，让 Agent 调用 `server_status`，确认 `view.ready` 为 `true`，再进行同步。

## 设计列表为空，或者查不到节点

首次连接时列表为空是正常的。同步后在 View 中确认设计已出现，复制实际返回的链接或标识。节点与模块标识以当前设计数据为准，避免使用旧稿中的引用。设计源文件修改后，重新同步并让 Agent 查询当前概览。

## View 无法打开

使用当前 `server_status` 或同步结果返回的地址，确认 Runtime 仍在运行。检查是否配置了多个实例或存在端口冲突，再查看客户端中的 MCP 错误信息。可先禁用重复配置并重启所用客户端，无需删除设计数据。

## 截图或合图失败

确认本机安装了支持的浏览器，且 `server_status` 中 View 已就绪。先尝试一个小模块，记录失败步骤和错误信息。若仅特定设计失败，可以提供脱敏后的最小示例，帮助判断是渲染环境还是图层内容问题。

## 字体、文字换行或宽度与设计不同

检查本机是否具有对应字体，并核对字重、字号、行高和目标视口。字体替换会影响布局。需要导出字体子集时，先确认对应字体许可允许在你的项目中分发和使用。

## 为什么图片里有文字，页面又出现一遍？

某些资源已经烘焙了文字或构件。让 Agent 检查节点的图片内容元数据，确认哪些内容已经包含在图片中。需要动态文案时，再决定如何拆分图片与可编辑内容。

## 为什么图片在自己机器上能用，部署后失效？

Runtime 返回的本地路径、资源 URI 和临时 URL 用于读取或转存。将实现需要的资源复制到项目管理的资源目录，再使用项目内路径；不要直接在业务代码中依赖本地 Runtime 地址。

## 如何把设计链接发给同事？

本地链接只指向访问者自己的机器，不能作为跨机器共享链接。同事需要在自己的环境中同步或取得可用设计数据。公开反馈时请描述问题，并提供经过脱敏的截图或最小示例。

## 能自动理解所有交互和多状态吗？

静态设计可以提供多个状态的外观，具体行为还需要业务需求。请告诉 Agent 哪个状态对应什么条件、按钮触发什么动作。模块差异可以辅助比较，不能替代业务定义。

## 可以保证一次生成就完全一致吗？

当前不作这种保证。设计质量、模型能力、字体、资源、视口和项目约束都会影响效果。建议从小模块开始，预览后指出具体偏差，让 Agent 回查并修正。

## 不知道版本还能反馈吗？

可以。表单接受“不清楚”，截图和日志为选填项。尽量说明你在哪一步遇到问题、预期是什么、实际发生了什么；维护者可以继续协助补充信息。
